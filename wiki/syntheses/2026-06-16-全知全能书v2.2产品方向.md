## 三、v2.2 架构设计

### 3.1 数据流

```
主人(飞书消息)  ──>  我(AI)  ──>  写 .md 到 wiki/  ──>  重编 graph.json/index.html  ──>  浏览器(只读繁星)
   [输入]            [编辑器]         [数据]                  [编译]                          [展示]
```

**关键约束**：
- 浏览器端**只读**（不编辑）
- 编辑入口 = 飞书消息
- 编译 = AI 助理 + cron + 心跳机制（已存在，AGENTS.md 协议）

### 3.2 节点层级结构（递归嵌套散点）

```
L1: 11 颗大星
    ├─ "生活" 在画布中心 (0, 0)
    └─ 其他 10 颗散在 "生活" 周围 (r ∈ [400, 800])

L2: ~30 颗中等星
    └─ 散在各自 L1 内 (r ≤ 80)

L3: ~18 颗小星
    └─ 散在各自 L2 旁 (r ≤ 30)

L4: 750+ 颗最小星
    └─ 散在各自 L3 旁 (r ≤ 12)

边：仅 L4 之间画关联线（v1.0 backlinks 已有数据，1696 个 wikilink）
```

### 3.3 节点大小与颜色

| 层级 | 节点半径 | 颜色 |
|------|----------|------|
| L1 | 25 px | 按 L1 学科（11 色） |
| L2 | 12 px | 继承 L1 父节点色 |
| L3 | 6 px | 继承 L1 祖先色 |
| L4 | 3 px | 继承 L1 祖先色 |

### 3.4 LOD 切换（4 档）

| k 范围 | 显 |
|--------|------|
| k < 0.4 | 全隐（极远） |
| 0.4 ≤ k < 0.6 | L1 |
| 0.6 ≤ k < 0.85 | L1 + L2 |
| 0.85 ≤ k < 1.10 | L1 + L2 + L3 |
| 1.10 ≤ k ≤ 1.50 | L1 + L2 + L3 + L4 + 边 |

### 10.2 绿联 DXP4800Plus 部署关键点

主人 NAS 是绿联 DXP4800Plus（N100/类 x86_64），nowen-note **明确支持**：

- 镜像大小：**~85–95MB**（Alpine 优化后，slim 版本原 238MB）
- 运行时内存：空闲 100–200MB / 中等使用 300–500MB
- 部署三步：(1) `docker build -t nowen-note .` + `docker save` → (2) 绿联 Docker 本地导入 → (3) 端口 3001:3001 + **卷 `/app/data`**（⚠️ 必须是 `/app/data` 不是 `/data`，这是官方专门强调的踩坑点）
- 镜像 Dockerfile 已声明 `VOLUME ["/app/data"]`，绿联面板下拉框**自动预填**该路径
- JWT 密钥在首启时**自动生成**并持久化到 data 卷，零配置
- **结论：绿联 DXP4800Plus 完全能跑**

### 10.3 借鉴清单（按 ROI 排序）

主人问"全知全能书有哪些可以借鉴的地方"，按"投入产出比"排序：

| # | 借鉴项 | 说明 | ROI | 优先级 |
|---|--------|------|-----|--------|
| 1 | **AI 自动元数据** | 标题生成 / 标签推荐 / AI 总结 | 改 frontmatter 脚本的事，半天能跑 | ⭐⭐⭐ |
| 2 | **RAG 知识问答** | "问我的知识库"功能，本地 Ollama 私有问答 | 999+ 节点已就绪，技术上零成本，**与 Karpathy LLM Wiki 范式天然延伸** | ⭐⭐⭐ |
| 3 | **浏览器剪藏扩展** | 主人看 ChatGPT/Claude 回答或新闻时一键存档 | 需要新写轻量工具 → 落盘到 `wiki/sources/...` | ⭐⭐ |
| 4 | **附件对象存储 S3/R2/MinIO** | 图（分镜草图）/PDF/录音存到独立对象存储 | 绿联 NAS 自带 S3 兼容层可直接用 | ⭐⭐ |
| 5 | **审计日志 + Webhook** | 重要修改自动发飞书提醒 | git commit 也能做，Webhook 更实时 | ⭐⭐ |

| 7 | **编辑器双引擎** | Tiptap 富文本 + Markdown | "给非技术用户用" 才会用，优先级低 | ⭐ |
| 8 | **多端 PWA** | 主人"随时访问"愿景对应 | 全知全能书现在是桌面浏览器，需 PWA | ⭐⭐ |

**最建议先做的 3 个**：

- **RAG 飞书机器人**：主人飞书发问 → 召回 → LLM 答 → 飞书回，**一天能搭起来**
- **搜索结果 AI 总结**：在现有 search-index.json 上加 LLM 总结层

### 10.4 避坑清单（nowen-note 哪些设计**不**适合全知全能书）

| nowen-note 的设计 | 为什么**不**适合全知全能书 |
|---|---|
| **SQLite 私有格式** | 全知全能书核心理念是**纯 .md 长期可读**，SQLite 数据不透明 |
| **GPL-3.0** | 主人是个人项目，不需要传染性；参考即可，不引代码 |
| **4 档权限分享 / 访客留言** | 全知全能书纯个人用，飞书已替代分享需求 |
| **任务 / 看板 / 甘特图** | 主人不需要，徒增噪音；Notion / 飞书任务可替代 |
| **说说 / 朋友圈** | 飞书替代 |
| **思维导图编辑器** | 全知全能书图谱本身比思维导图强（递归嵌套散点） |
| **Tiptap 富文本编辑** | 主人习惯 raw markdown，富文本编辑会破坏 frontmatter |
| **预编译打包/不读源文件** | 跟全知全能书"主人发飞书消息 → AI 写入"的核心理念相悖 |

### 10.5 全知全能书 vs nowen-note 定位对比

| 维度 | 全知全能书 wiki-graph（主人） | nowen-note |
|---|---|---|
| 形态 | **只读展示层** + 静态 .md 生成 | 完整 CRUD 应用（Web/桌面/手机） |
| 数据 | 纯 **Markdown**（git 友好） | SQLite（私有格式） |
| AI | 暂无（待开发） | ✅ 内嵌 RAG 多模型 |
| 协作 | ❌ 纯个人 | ✅ 4 档权限 |
| 任务/思维导图 | ❌（图谱已替代） | ✅ |
| 长期可读性 | ✅ 20 年后还能打开 | ⚠️ 依赖项目存活 |
| 迁移成本 | — | 双向迁移有工具但麻烦 |

**结论**：两者是**不同路线**的产品，可借鉴的是"功能思路"而非"代码实现"。
