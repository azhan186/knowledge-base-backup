## 一、核心流程 (L1/L2/L3/L4 文章处理)

**所有入站文章必须按此流程分类。** 流程分 4 步：

```
┌─────────────────────────────────────┐
│  0. 收到文章 (docx/pdf/网页/笔记)     │
└────────────────┬────────────────────┘
                 ↓
┌─────────────────────────────────────┐
│  1. 选 L1 (11 个学科门类之一)         │
│     跨学科 → 交叉学; 否则选对应学科  │
└────────────────┬────────────────────┘
                 ↓
┌─────────────────────────────────────┐
│  2. 选 L2 (该 L1 下的二级学科类)       │
│     例: 理学→数学/物理/天文学类/...    │
└────────────────┬────────────────────┘
                 ↓
┌─────────────────────────────────────┐
│  3. 选 L3 (该 L2 下的具体主题)         │
│     ⚠ 现有无合适 → 停下问主人新建     │
└────────────────┬────────────────────┘
                 ↓
┌─────────────────────────────────────┐
│  4. 命名 L4 → 存到 L3 文件夹下        │
│     文件名: source-YYYY-MM-DD-{标题}.md│
└─────────────────────────────────────┘
```

### 1.1 L1 选择 (11 个, 暂定)

| L1 | 范围 | 典型关键词 |
|----|------|----------|
| 理学 | 基础研究 | 数学、物理、天文、地球、生物、化学 |
| 工学 | 工程应用 | 材料、电子、航空航天、能源、机械 |
| 医学 | 临床医学 | 临床、疾病、药物、治疗、护理 |
| 哲学 | 思辨/社会 | 哲学、宗教、社会学、心理学 |
| 文学 | 人文 | 文学、语言、新闻、艺术 |
| 经济学 | 经济金融 | 投资、股票、基金、宏观 |
| 历史学 | 历史 | 朝代、事件、文明 |
| 管理学 | 组织/管理 | SOP、管理、公共、HR |
| 艺术学 | 艺术创作 | 视觉、音乐、表演 |
| 交叉学 | **跨学科默认** | 任何 2 个 L1 交织的内容 |
| **生活** | 主人个人 | vlog 设备、个人 NAS、爱好 |

**L1 暂定 11 个**, 主人 2026-06-16 01:10 确认。**未来随知识库知识增加可能扩充**, 但**不擅自添加**, 必须主人批准。

**L1 决策规则**:
- ❓ 单一学科能装下 → 放对应 L1
- ❓ 跨 2+ 个 L1 → 放**交叉学**
- ❓ 不确定 → 🛑 **停下问主人**

### 1.2 L2 选择 (GB/T 4754 学科类)

每个 L1 下的 L2 列表见 `wiki/syntheses/知识库-L2-对照表.md` (待建)。

**核心规则**:
- L2 是 GB/T 4754 学科类
- 选最匹配的子类
- 不确定 → 🛑 问主人

### 1.3 L3 选择 (主题) ⚠ 主人审批制

L3 是**主题**——该 L2 下这篇文章最相关的具体概念。

**🛑 铁律**: 现有 L3 列表见 `wiki/sources/{L1}/{L2}/` 下各文件夹。

- 找不到**非常合适**的 L3 → 🛑 **必须停下问主人**, 不要自己新建
- 主人明确指定新建 → 走 §1.3.1 流程

**L3 决策规则**:
- 看到标题/关键词 → 想想: 这是"主题"还是"文章"?
  - "AI 幻觉" → 主题 (现有 L3)
  - "AI 幻觉入门篇" → 文章 (放到 L3 = AI幻觉 下)
- L3 名字 ≤ 4 个汉字
- 不带日期, 不带版本号
- 不确定 → 🛑 问主人

#### 1.3.1 L3 新建流程 (主人批准)

⚠ 禁止 AI 自行创建 L3 文件夹。

```
AI: "现有 L3 列表: [A, B, C]。文章 X 都不匹配, 需要新建 L3 吗?"
   选项 1: "复用 B" (主人在 X 标题上加注释说明相关性)
   选项 2: "新建 D, 名字: ____"
   选项 3: "改 L1/L2 (我选错了, 重新走流程)"
主人: [回复]
AI: 收到, 走对应流程
```

**新建 L3 的规则**:
- 名字 ≤ 4 个汉字
- 名实相符 (不要 "其他" / "杂项" 这种)
- 触发新 L3 的文章数 ≥ 3 篇才正式保留 (避免偶然性)
  - **例外**: 主人明确指示的新 L3 (如 "建 数字孪生医疗"), 不需要等 3 篇, 立刻成立

### 1.4 L4 保存 (文件本身)

- **文件名**: `source-YYYY-MM-DD-{标题}.md`
  - 破折号 `-` 不用下划线 `_`
  - 日期格式 YYYY-MM-DD
  - 标题用中文, 不用空格的用 `_` 替代
- **路径**: `wiki/sources/{L1}/{L2}/{L3}/{L4}.md`
- **frontmatter 必填字段**:
  - `title`, `type: source`
  - `subject: "{GB/T 4754 学科码}"` — 必填
  - `tags: [..., L1, L2, L3]` — 必含 (用于反向查询)
  - `sources: []` 或前置素材
  - `last_updated: YYYY-MM-DD`
- **首行路径声明**: 文件正文第一行 `L1-xxx/L2-xxx/L3-xxx/L4-xxx` (用于 grep)

## 四、命名规范

- **必填**: `source-YYYY-MM-DD-{标题}.md`
- ✅ 用破折号 `-` (不用下划线 `_`)
- ✅ 日期在前 (ISO 8601)
- ✅ 标题用中文
- ❌ 不用空格 (用 `_` 替代)
- ❌ 不带版本号 (e.g., v2, 修订)

例: `source-2026-06-15-量子力学深入篇.md`

- 中文简短 (1-4 字)
- 不要带日期
- 不要带版本号
- 用 `_` 替代空格

例: `AI幻觉`, `慢性肾脏病`, `人造太阳`

### 4.3 L2 文件夹名 (学科类)

- GB/T 4754 标准名
- 例子: `物理学类`, `天文学类`, `智能科学与技术`

### 4.4 L1 文件夹名 (学科门类)

- 11 个固定: 理学 / 工学 / 医学 / 哲学 / 文学 / 经济学 / 历史学 / 管理学 / 艺术学 / 交叉学 / 生活

## 五、frontmatter 规范

每个 source 文件**必须**有完整 frontmatter:

```yaml
---
title: "AI幻觉入门篇"                    # 文件标题
type: source                              # 固定
subject: "520 计算机科学与技术"            # GB/T 4754 学科码 + 名
tags: [AI, 幻觉, LLM, 入门, 交叉学, 智能科学与技术, AI幻觉]  # 关键词 (必含 L1/L2/L3)
sources: [原始 URL 或文件路径]               # 原料来源
last_updated: 2026-06-16                   # 必填
---
L1-交叉学/L2-智能科学与技术/L3-AI幻觉/L4-AI幻觉入门篇
```

**特别强调**:
- `subject` 必填, 用 GB/T 4754 学科码
- `tags` 必含 **L1/L2/L3** 三个值 (用于反向查询)
- 文件正文第一行**必含 L1-xxx/L2-xxx/L3-xxx/L4-xxx** 路径 (用于 grep)

## 七、酒店 SOP 处理流程 (v1 保留)

### 7.1 单条处理
1. **接收文件** → 保存到 `Raw Sources/上海万豪侯爵酒店资料/`
2. **读取内容** → 用 python-docx 解析中英文
3. **生成 Wiki** → 转换为 `.md` 文件保存到 `上海万豪侯爵酒店资料/`
4. **记录日志** → 在 `Wiki/log.md` 记一行摘要

### 7.2 批量处理 (SOP 数量多时)
- 按系列分组: DY(洗衣房) / PA(公共区域) / Floor(楼层) / FC(制服)
- 每组完成后统一通知用户, 避免每条都回复 "ok"

## 八、Wiki 页面管理 (v1 保留)

### 页面状态
- **草稿** `🟡`: 刚建立, 内容不完整
- **已验证** `✅`: 内容经人工核对, 无误
- **已过时** `❌`: 被新版本替代

### 更新规则
- 每次更新页面, 在文件末尾加一行更新日志:
  ```markdown
  ## 更新记录
  - 2026-05-15: xxx
  ```
- 大幅修改时注明更新原因

## 九、沉淀规则 (v1 保留)

> 什么值得进入知识库？

**应当沉淀**:
- 有知识价值的信息 (中英文术语、工作流程、决策逻辑)
- 经过验证的组织结构、岗位信息
- 原创分析成果 (如组织架构冲突分析、偏差正常化理论)

**不应沉淀**:
- 纯聊天记录 (对话日志交给 memory/)
- 未经核实的推测
- 个人信息 (除非用户明确要求)

**沉淀原则**:
> 知识库是给「未来的自己」看的。要经得起一年后回头翻阅。
