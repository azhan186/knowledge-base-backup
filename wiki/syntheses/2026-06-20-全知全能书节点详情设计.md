## 二、3 个决策（2026-06-20 15:09 主人拍板）

### 决策 1：显示哪个 md → **A + B 双面板**

| 来源 | 例子 | 角色 |
|------|------|------|
| **A) Raw Sources**（图书馆/Raw Sources/.../*.md） | `图书馆/Raw Sources/AI与科技/2026-05-27_人工智能全面解析.md` | **原文面板**（完整笔记） |
| **B) Wiki 编译产物**（wiki/sources/.../source-*.md） | `wiki/sources/交叉学/智能科学与技术/人工智能 AI/source-2026-05-27-人工智能全面解析.md` | **结构化摘要面板**（已提炼） |

**布局**：
```
┌─────────────────────────────────────────────┐
│  L4 节点: 人工智能全面解析                  │
├──────────────────────┬──────────────────────┤
│                      │                      │
│  📄 原文（A）        │  🗂️ 摘要（B）       │
│  Raw Sources         │  Wiki 编译           │
│                      │                      │
│  [完整 md 渲染]      │  [结构化摘要]        │
│                      │  - 核心概念          │
│                      │  - 双向链接          │
│                      │  - 相关笔记          │
│                      │                      │
└──────────────────────┴──────────────────────┘
```

**理由**：原文给完整信息，摘要给快速决策视角。两个互补。

### 决策 2：显示多长 → **C 折叠展开**

| 模式 | 是否选 | 理由 |
|------|--------|------|
| A) 全文直接渲染 | ❌ | 长文卡顿、视觉负担 |
| B) 头 500 字 | ❌（CHANGELOG 早期定调） | 看不全，主人已放弃 |
| **C) 默认头 500 字 + 点「展开」看全文** | ✅ | **两全其美** |

**实现要点**：
- 默认只显示前 ~500 字 + 「展开全部 ▼」按钮
- 展开后：完整 md 渲染 + 「收起 ▲」
- 切换有过渡动画（不突然）

### 决策 3：怎么打开 → **A + B + D 三层**

| 交互层 | 触发 | 内容 |
|--------|------|------|
| **A) Hover 悬浮预览** | 鼠标悬停 200ms | 500 字摘要 + 元数据（小框） |
| **B) 点击弹窗** | 单击节点 | 双面板（原文 + 摘要），默认头 500 字 |
| **D) 全屏阅读模式** | 双击 / 弹窗内「全屏」按钮 | 单独路由 `/read?id=L4-xxx`，完整 md 渲染 + 暗色主题 |

**理由**：快速浏览 → 详细阅读 → 沉浸阅读，三层覆盖所有场景。

## 三、前置问题：节点 → md 映射（2026-06-20 15:09 主人问）

### 现状

`v2.3-canvas.html` 用 mock 数据，每个节点只有 id（如 `L4-27`），**没存 md 路径**。

未来接入真实数据时，必须解决："节点 id ↔ md 文件路径" 的映射。

### A 方案：graph.json 加 md_path 字段

```json
{
  "id": "L4-xxx",
  "level": 4,
  "md_path": "图书馆/Raw Sources/AI与科技/2026-05-27_xxx.md",
  "wiki_path": "wiki/sources/.../source-2026-05-27-xxx.md"
}
```

- ✅ O(1) 查
- ❌ md 移动/重命名 → 节点断链 → 需重新生成 graph.json
- ❌ 长期维护：每次 md 变更都要 reindex

### B 方案：按 id 反查（扫库）

- 每次查 → 扫 `图书馆/Raw Sources/` + `wiki/sources/`
- ✅ 自动跟进 md 移动/重命名
- ❌ 慢（每次查都要扫库）
- ❌ 需要建立稳定的 id ↔ md 映射规则

### **混合方案（A + B 的反向索引）**：长期维护最优 ✅ **主人 2026-06-20 15:14 最终决策**

**推荐**：
- graph.json 不存 md_path（保持纯净）
- 单独建反向索引 `wiki/.index/node_to_paths.json`（**路径 A，主人确认**）：
  ```json
  {
    "L4-人工智能全面解析": {
      "raw": "图书馆/Raw Sources/AI与科技/2026-05-27_xxx.md",
      "wiki": "wiki/sources/交叉学/智能科学与技术/人工智能 AI/source-2026-05-27-xxx.md"
    },
    ...
  }
  ```
- **增量更新**：每次 wiki 编译任务（凌晨 cron）跑完后，扫描新生成的 wiki/sources/，增量更新反向索引
- **md 移动检测**：每天扫一次原 md 是否还在原位（mtime 检测），缺失则在反向索引里标记「断链」+ 飞书通知主人

**为什么混合更好**：
- A 提供 O(1) 查（性能好）
- B 的反向索引让 md 移动/重命名自动跟进（不脆）
- 增量更新让索引维护成本低（只在编译时跑）
- 主人说"长期更新维护"——混合方案避免了纯 A 的脆性 + 纯 B 的性能问题

**为什么选路径 A**：
- 反向索引跟随知识库 GitHub 备份（每天 04:30），**数据不丢**
- 在知识库内，与 wiki 编译产物同源，维护逻辑统一
- 不污染 wiki-graph/ 目录（保持图形可视化代码独立）

## 四、实现规划（决策落地后启动）

### Phase 1：数据层（节点 → md 映射）

1. **写反向索引脚本** `wiki-graph/build-reverse-index.py`：
   - 扫 `wiki/sources/` 所有 source-*.md
   - 从 frontmatter 读 `raw_sources` 字段
   - 生成 `wiki/.index/node_to_paths.json`
2. **集成到凌晨 cron**：与 wiki-compile 任务并行
3. **断链检测**：每天扫一次，飞书通知

### Phase 2：API 层（auth-server.py 加动态路由）

```python
# 预览 API（hover 用）
GET /api/preview?id=L4-xxx
  → 返回头 500 字 + 元数据 (title, tags, mtime)

# 全文 API（点击弹窗用）
GET /api/full?id=L4-xxx
  → 返回完整 md 内容

# 双面板 API
GET /api/dual?id=L4-xxx
  → 返回 { raw: "...", wiki: "..." } 两个文件全文
```

### Phase 3：前端层（v2.3-canvas.html 加交互）

1. **Hover 预览**：监听 mouseenter，200ms 防抖，调 `/api/preview`，D3 tooltip 显示
2. **点击弹窗**：监听 click，调 `/api/dual`，渲染双面板
3. **展开/折叠**：默认 500 字，「展开全部」按钮
4. **全屏模式**：双击 → 跳 `/read?id=...`，单独页面 md 渲染

### Phase 4：数据接入（v2.4 真正接库）

- 替换 mock 数据 → 读真实 graph.json
- 节点 id 用**语义化命名**（如 `L4-AI幻觉-defense`）而非数字
- 保证反向索引能匹配

## 八、渲染细节规范（2026-06-20 15:33 主人明确指定）

主人给了示例：「**AI幻觉入门篇**」md 原文 → 清爽阅读视图。

### 渲染规则表

| md 原文 | 渲染后 | 说明 |
|---------|--------|------|
| `---...---` (YAML frontmatter) | **隐藏** | 元数据不干扰阅读 |
| `L1-.../L2-.../L3-...` (路径标记) | **隐藏** | 开发用面包屑 |
| `# H1` | 大号字 | 视觉显著，但不用 `<h1>` 元素 |
| `## H2` | 中粗体 | 视觉中等 |
| `### H3` | 粗体 | |
| `**加粗**` | **粗体**（不显示星号） | |
| `> 引用` | **保留** | 引用块样式 |
| `- 列表` | **保留** | 短横线列表 |
| `[[wikilink]]` (含 `— 主卡` 这类后缀文本) | **整段隐藏**（2026-06-20 15:48 主人明确） | 主人原话："原文也是这样" → wikilink 与 frontmatter / 路径标记同等待遇 |

### 主人原话参考

> "我希望是这样显示的：AI幻觉入门篇
> > 系列：AI幻觉（入门 → 深入 → 资深 → 专家）
> 核心定义
> AI幻觉（AI Hallucination）：AI 模型生成内容流畅、自信、煞有其事..."

**特点**：完全去除源码符号（`#`、`**`、`[[...]]`），只保留：
- 标题（视觉化）
- 引用块（>）
- 列表（-）
- 加粗（视觉）

### 与「源码模式」的关系

如果未来主人调试需要看原文，可加「</> 源码」按钮切换。但**默认就是这个纯文字视图**。
